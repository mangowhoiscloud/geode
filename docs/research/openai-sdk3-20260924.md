# OpenAI SDK 3 compatibility decision — 2026-09-24

Retrieved 2026-09-24. This is a dependency and local transport audit; no model
request, credential inspection, or backend acceptance test was performed.

## Release decision

Keep the current resolved `openai==2.45.0` and declare the supported requirement
as `openai>=2.45.0,<3`. Retain HTTPX 1 for the OpenAI-family and Anthropic clients.
The model refresh does not require a generated model-name enum update: SDK 2's
`ResponsesModel` accepts strings. Existing OpenAI, Codex, and GLM clients continue
to use configured timeouts, application-owned retries (`max_retries=0`), and
Codex's explicit zero idle-connection limit.

SDK 3 migration is deferred because the current audit dependency graph cannot
retain its supported versions with SDK 3. Do not resolve this by downgrading
Harbor, bypassing dependency metadata, or claiming that an old unbounded
requirement proves runtime compatibility.

An exploratory `uv lock --upgrade-package openai` with `openai>=3.19,<4`
selected LiteLLM 1.82.6, Harbor 0.2.0, and inspect-harbor 0.4.17. LiteLLM 1.82.6
was published March 22 and only declares `openai>=2.8`; its absence of an upper
bound predates SDK 3. The candidate lock was discarded. Repeating resolution
while constraining `inspect-harbor==0.5.4` and `harbor==0.8.0` failed: every
eligible stable LiteLLM version required SDK 2. A Harbor-only constraint let the
resolver instead remove Harbor via inspect-harbor 1.0.0, so it was also rejected.
The final lock preserves every package version and artifact; only GEODE's own
SDK requirement metadata changes.

## Anthropic SDK 1 boundary

The current official Anthropic SDK is **1.8.0**, published September 22; the
retained, locally verified version is **0.116.0**. The requirement is bounded to
`anthropic>=0.116.0,<1` until the transport and audit consumers migrate together.
Unlike OpenAI 3's temporary legacy-client allowance, Anthropic 1 rejects an old
HTTPX custom client at construction. This is an immediate fresh-install failure
with the existing GEODE client builder, independent of the selected model.

Sources: [versioned package metadata](https://pypi.org/pypi/anthropic/1.8.0/json),
[1.8.0 changelog](https://github.com/anthropics/anthropic-sdk-python/blob/v1.8.0/CHANGELOG.md),
[pinned migration guide](https://github.com/anthropics/anthropic-sdk-python/blob/v1.8.0/MIGRATION.md).
Its dependencies include HTTPX2 `>=2,<3`, Python `>=3.10`, Pydantic `>=1.10,<3`,
and AnyIO `>=4.1,<5`. GEODE's Python requirement is already sufficient.

The migration guide also removes `temperature`, `top_p`, and `top_k` keyword
arguments from message methods. Older supported models still accept these API
fields, but the SDK requires `extra_body`; modern sampling-rejecting models
should continue to omit them. GEODE's shared Claude request builder still uses
sampling keywords for older models, and its custom client, timeout/limits, and
Anthropic error fixtures use HTTPX 1. Those are actual migration owners.
Other removed surfaces include the legacy completions API, schema-dict
`output_format`, and synchronous parsing of async raw responses; the inspected
GEODE Claude call path uses none of those removed forms.

There is no active direct dependency requirement imposing `<1` on Anthropic in
the current lock. **Metadata compatibility alone is insufficient:** the
published [Inspect 0.3.252 wheel](https://pypi.org/pypi/inspect-ai/0.3.252/json)
constructs `params["temperature"]`, `params["top_p"]`, and `params["top_k"]` for
legacy models and passes them to message methods. That audit path is incompatible
with SDK 1. The published [Inspect 0.3.268 wheel](https://pypi.org/pypi/inspect-ai/0.3.268/json)
moves sampling into `extra_body` and supports Anthropic HTTPX2 clients. It also
changes OpenAI transport defaults to HTTPX2, so retaining OpenAI SDK 2 requires
separate constructor/request verification before accepting that companion
upgrade. No such combined runtime compatibility is established here.

LiteLLM 1.85.1's Anthropic handler sends its own HTTPX requests rather than
constructing an Anthropic SDK client. Its `anthropic[vertex]==0.84.0` constraint
belongs to the unselected `proxy-runtime` extra; it is not an active SDK 1
resolver blocker in GEODE. A future SDK 1 slice must verify the actual Inspect
and GEODE clients, preserve OpenAI's HTTPX 1 boundary where required, and retain
all audit functionality. A global `httpx2.alias_httpx()` is not an acceptable
library-level migration because it changes unrelated consumers process-wide.

## Request surface versus SDK types

The [SDK 2.45 Responses resource](https://github.com/openai/openai-python/blob/v2.45.0/src/openai/resources/responses/responses.py)
accepts arbitrary model strings and exposes `extra_body` for request properties
missing from generated keyword signatures. Existing reasoning, text verbosity,
`max_output_tokens`, and `prompt_cache_options` fields already have typed request
surfaces. The [SDK 3.19 request schema](https://github.com/openai/openai-python/blob/v3.19.0/src/openai/types/responses/response_create_params.py)
adds newer service-tier spellings and cache prewarming. SDK 2.45 still types
`priority` rather than `fast`/`ultrafast`, and lacks the prewarm option.

A local HTTPX `MockTransport` test confirms that SDK 2.45 sends the arbitrary
`gpt-6-sol` model ID and `extra_body` fields `service_tier="fast"` and
`prompt_cache_options={"prewarm": true}` intact to a synthetic Responses route.
This establishes serialization only. It does not enable these controls in
GEODE, establish route/account/model acceptance, or authorize billing changes.
Before exposing a control, bind the official provider contract to the PAYG or
subscription route and wire its request policy and response/accounting consumer.
New native tools also need their output parser and dispatch path; sending a
new tool schema alone does not provide support.

## Migration scope when the dependency graph permits it

1. Re-resolve the complete base and optional dependency graph with compatible
   LiteLLM/Harbor/Agents versions, preserving audit behavior; review all changes.
2. Move `_openai_common._build_async_httpx_client` to HTTPX2 `AsyncClient`,
   `Limits`, and `Timeout`. Both OpenAI/GLM and Codex builders use this owner;
   retain Codex's keep-alive override, configured timeouts, and zero SDK retries.
   Preserve Anthropic's independent HTTPX 1 client and response hooks.
3. Update OpenAI error fixtures in `test_classify_llm_error.py`,
   `test_source_routing_regression.py`, and `test_compaction_phases.py` to HTTPX2
   request/response objects. Keep Anthropic fixtures on HTTPX 1.
4. Check SDK parsing and streaming against actual local mocked responses,
   including the Codex null-output shim. A release note about null *message
   content* does not prove that null `Response.output` is fixed.
5. Document the migration guide's certificate trust change: HTTPX2 uses the OS
   trust store instead of certifi by default. Preserve explicit corporate CA
   configuration through supported environment variables or SSL contexts.

`providers/glm.py` and `tools/document_ingest.py` instantiate SDK defaults with
numeric timeouts; they require verification with the new SDK but no custom
HTTPX2 construction. Existing unrelated HTTPX clients remain with their owners.
The SDK's temporary legacy-client runtime compatibility is not the target
architecture; SDK 3 static types require HTTPX2.

## Local verification

The accepted code deduplicates Codex HTTP construction without changing its
transport library. Tests construct real SDK clients with dummy credentials and
inspect configured pool limits, all timeout components, retry count, route,
headers, and client closure. Adapter checks cover OpenAI PAYG, GLM PAYG, and GLM
Coding Plan. Source-text pins that demanded duplicated construction are replaced
by these behavioral checks. Existing Codex parser regression tests remain.

SDK 3 was researched, not installed or validated as the runtime. No remote CI
result or live provider compatibility is claimed by this document.
